Tutorial

        
A short, practical guide to running the store. Read it once — it covers the few things that cause 90% of problems.

      

      


        

          
Create your admin account

          

            
The admin page does not create accounts (that would let anyone in). An account for admin@mwemtsi.co.tz already exists. To add another one, the owner does this:

            
    
              
  1. Supabase dashboard → Authentication → Users → Add user.
    2. 
              
  2. Use the login address admin@mwemtsi.co.tz (shown under the password box — tap “use another account” to sign in with a different one) and choose a strong password. Tick “auto confirm” if shown.
    3. 
              
  3. SQL Editor → run:
    4. 
            

            
update public.profiles set role = 'admin' where email = 'admin@mwemtsi.co.tz';

            
Now come back here and enter only that password.

          

        


        

          
Add a product

          

            
Products → + Add product. Give it a name, a price in TZS, a category (Men/Women) and a position number.

            
    
              
  • Lower position = earlier in the grid.
    • 
              
  • Leave Active ticked so it appears publicly.
    • 
              
  • You can add the photo now or later with “Change image”.
    • 
            

          

        


        

          
Edit a product

          

            
Change any field and press Save on that row. The price must be a number (no “TZS” needed — it is added automatically). If a save fails you will see the database error in the corner; the usual cause is an expired session — sign out and back in.

          

        


        

          
Upload product photos

          

            
On a product row press Change image, pick a file, then Save. The file is checked before it uploads — if it does not meet the rules the upload is refused and the reason is printed under the row.

            
    
              
  • JPG, PNG, WebP or AVIF. Under 5 MB.
    • 
              
  • At least 800×800 and up to 3000×3000 pixels.
    • 
              
  • Between 1:2 and 2:1. A 4:5 picture fills the card best.
    • 
              
  • The old photo is not deleted from Storage; it simply stops being referenced.
    • 
            

          

        


        

          
Replace a site photo or video

          

            
Media tab → find the slot (for example “Home — intro video”) → Choose file → it uploads and goes live. Each card prints the exact requirements for that slot, so you can check a file before you pick it.

            
    
              
  • Video: MP4 (H.264) or WebM. At least 1280×720, up to 1920×1080, 16:9. Between 3 and 20 seconds, under 20 MB.
    • 
              
  • Photo: JPG, PNG, WebP or AVIF. At least 1280×720, up to 3840×2160, 16:9. Under 5 MB.
    • 
              
  • A poster frame is captured from a video automatically, so the slot never shows the previous shot.
    • 
              
  • Uploading can take a while on slow connections — wait for “Live” before checking the site.
    • 
            

          

        


        

          
Why a file gets refused

          

            
Every upload is inspected in your browser before anything is sent. A file is refused when it would visibly clash with the page:

            
    
              
  • the wrong shape — a portrait photo in a slot that is cropped to 16:9 would cut the subject off;
    • 
              
  • too small — it would look blurry on a phone;
    • 
              
  • too big — a heavy file makes the page slow on mobile data;
    • 
              
  • the wrong codec — an HEVC or AV1 MP4 plays as a black box on some browsers.
    • 
            

            
Amber messages are only advice: the upload still goes ahead, but the picture will not fill the frame quite as well.

          

        


        

          
Why a bad upload cannot break the site

          

            
There are three layers of protection, and a file has to get past all of them.

            
    
              
  1. Before upload. The file is measured and decoded in your browser. A file that would clash with the page is refused, so it never reaches Storage.
    2. 
              
  2. On the public page. Public pages never point straight at a new file. They preload it first, and only then swap it in. If the file is missing, the wrong type, too heavy or the network drops, the page silently keeps the bundled original.
    3. 
              
  3. In the database. Only a signed-in admin can write a product or a media override. A stranger with the public key can read the catalogue but cannot change it.
    4. 
            

            
You may need a hard refresh (Ctrl/Cmd + Shift + R) to see a change because browsers cache video.

          

        


        

          
Undo a replacement

          

            
Media tab → Reset to default. This removes the override row; the site returns to the media that shipped with it. The uploaded file stays in Storage and can be re-used.

          

        


        

          
Clean up duplicates

          

            
If a product appears twice, keep the one with the correct photo and press Delete on the other. Deleting is permanent — prefer unticking Active if you might want it back.

          

        


        

          
Security rules that keep the store safe

          

            
    
              
  • Never put the Supabase service_role key in these files. Only the publishable (anon) key is public, and it can only read.
    • 
              
  • Customers can no longer edit prices or upload images: the database refuses writes unless the request carries an admin session.
    • 
              
  • This page being reachable is harmless — without an admin role it can read nothing and write nothing.
    • 
              
  • Remove a departing staff member in Authentication → Users. Their session dies immediately.
    • 
            

          

        


      

    


    
    

      

        
FAQ

        
Answers to the questions that come up most often.

      

      

        

          I signed in but I only see “Not an admin”.
          
Your account exists but its profile role is still viewer. The owner must run update public.profiles set role = 'admin' where email = 'you@example.com'; in the SQL Editor, then you reload this page.

        

        

          “Invalid login credentials” — but the password is right.
          
Either the email is unconfirmed, or the account was created with a different password. In Supabase → Authentication → Users, confirm the email or reset the password, then try again.

        

        

          I saved a product and the public page did not change.
          
Hard-refresh the public page (Ctrl/Cmd + Shift + R). Check the product is Active and in the right category. If the row shows a red error, your session expired — sign out and in.

        

        

          I replaced a video and the old one is still playing.
          
Videos are cached aggressively. Hard-refresh. Also confirm the Media card says Live and not just “Uploaded”. Very large files may take a moment to propagate.

        

        

          Which video format and size should I use?
          
MP4 with H.264 video and AAC audio (or no audio) is the safest across phones and desktops. Aim for 720p, 10–20 MB, 10–20 seconds for background loops. A 60 MB 4K clip will work on fast Wi-Fi and struggle on mobile data.

        

        

          What is the maximum upload size?
          
The page enforces 10 MB for images and 50 MB for video. Supabase also has a project-wide file limit. If a file is rejected, compress it (Handbrake for video, Squoosh for images) and try again.

        

        

          Can a customer edit prices or upload pictures now?
          
No. The public product cards are read-only, and the database’s row-level security only allows writes from an authenticated admin. Hiding a button is not security; the policy is.

        

        

          Where are uploaded files stored?
          
In the Supabase Storage bucket media. The database table site_media stores which file each slot should use. Product photos store their URL on the product row.

        

        

          How do I add a second admin?
          
Create the account in Authentication → Users, then run update public.profiles set role = 'admin' where email = '…';. To demote someone, set the role back to 'viewer'.

        

        

          What happens if I delete a category by mistake?
          
Categories are fixed (men, women). Re-running schema.sql restores them. Products whose category disappears become uncategorised but are not deleted.

        

        

          Is it safe to share the code / GitHub repo?
          
Yes. The repo contains only the publishable key, which can read public data. Writes require a signed-in admin, and the service_role key is never in the repo.
